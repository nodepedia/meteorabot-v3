## Snapshot

Bot trading live untuk pool Meteora DLMM di Solana (auto-entry + exit deterministik + DCA + auto-swap). Jalankan dari `src/index.js`.

- Full ESM (`"type": "module"`), **tanpa build step / TypeScript**. Edit `.js` langsung.
- **Wajib Node 24.x** (dipatok `node -v`). Bukan sekadar preferensi: `postinstall` mem-patch dependency agar jalan di Node 24.
- Detail arsitektur & konfigurasi: `PROJECT_STRUCTURE.md` dan `README.md` (jangan duplikasi di sini).

## Keamanan runtime (penting)

- `npm start` benar-benar konek ke Solana RPC/Helius, Jupiter, GMGN, dan **bisa mengirim transaksi trading**. Selalu uji dengan `DRY_RUN=true` di `.env` dulu.
- Jangan jalankan bot sambil mengedit file state produksi (`state.json`, `pool.txt`, dll) — bisa bentrok.

## Jebakan repo

- **`npm install` menjalankan `postinstall`** (`scripts/patch-anchor.js`) yang mem-patch `@coral-xyz/anchor` + `@meteora-ag/dlmm` untuk ESM Node 24. Ganti/update dependency → jalankan `npm install` ulang, jika tidak bot gagal import.
- **Bot menulis ke `pool.txt`**: mengomentari (`#`) pool yang sudah selesai. Jangan biarkan `pool.txt` terbuka di editor saat bot jalan (save akan menimpa mark bot).
- File state runtime **git-ignored** dan tidak boleh di-commit: `state.json`, `pool.txt`, `decision-log.json`, `pnl-history.json`, `supertrend-cache.json`, `logs/`, `.env`, `state/` (antrean klik Telegram: `telegram-commands.json`, offset, katalog tombol).
- **Default strategi ada di `strat.conf`** (di-commit). Tuning dilakukan di sini lalu `git commit`, bukan di `.env`. Bila key sama, `strat.conf` **menang** atas `.env` (`loadEnv` di `src/config/env.js`).
- Tes memakai override env (`STATE_FILE`, `DECISION_LOG_FILE`, `PNL_HISTORY_FILE`) supaya tidak menyentuh file produksi — ikuti pola ini untuk tes baru.
- `test/smoke.test.js` mengimpor semua modul; kalau pindah/ganti nama file, update daftar `MODULES` di file itu.
- `scripts/pnl-report.js` **read-only** — tidak menyentuh `state.json`, tidak mengirim transaksi.
- Rahasia & setelan instance (wallet, RPC, API key, telegram, `DRY_RUN`) ada di `.env` (jangan pernah di-commit; `chmod 600 .env`).

## Alur domain singkat

- **Entry**: Supertrend 15m native (GMGN) bullish + harga real-time Jupiter ≤ garis → masuk (`first_touch`). Bearish = pool tidak dipantau. Dua cadence terpisah (refresh kandidat vs poll harga Jupiter). Gerbang daftar pool hanya `#` di `pool.txt` (tidak ada hitungan max entry). Kuota serentak: paling banyak 1 posisi non-DCA per strategi per pool — `spot` dan `bidask` (`bidask:double` / `token` / `sol` satu slot) boleh terbuka bersamaan di pool yang sama, tidak pernah 2 spot atau 2 bidask. DCA tidak memakai kuota itu. Entry `bidask:double` hanya ke pool `binStep >= BIDASK_DOUBLE_MIN_BIN_STEP` (default 100); di antara yang lolos dipilih fee/active TVL 30m tertinggi. Tidak ada yang lolos = skip siklus, baris tidak di-`#`. Spot tidak kena. DCA tidak pindah pool. Entry manual `bidask:sol`: baris `CA,size,,bidask:sol,ca,HARGA` (tanpa Supertrend). HARGA tanpa akhiran atau `usd` = USD per token; akhiran `sol` = SOL per token; token `now` (huruf besar/kecil, `CA,,,bidask:sol,ca,now`) masuk begitu harga terbaca, tanpa menyimpan arah dan tanpa menulis harga sekarang sebagai target. Rentang −50%/+15% dihitung dari harga bin aktif saat entry. Bila pool, sewa, duplikat, atau SOL kurang, baris `now` tetap menunggu. Arah sentuh disimpan di state (tahan restart), kunci mint+target+satuan: harga pertama di bawah target menunggu naik sampai >= target, di atas target menunggu turun sampai <= target, tepat di target masuk sekarang. Harga belum terbaca tidak menyimpan arah dan tidak masuk. Mengubah target atau menghapus/# baris menghapus arah. Setelah entry berhasil baris itu diberi # (termasuk baris CA 6 kolom berakhiran sol) supaya tidak masuk lagi setelah posisi tutup. Satuan USD langsung, atau harga token USD dibagi harga SOL; harga SOL yang tidak ada tidak memicu. Lalu pilih pool DLMM token/SOL (TVL >= `BIDASK_SOL_ENTRY_MIN_TVL_USD`, lebar <= `BIDASK_SOL_ENTRY_MAX_BINS`) dan buka posisi SOL-only BidAsk; bin atas kosong. Setelah itu exit/rebalance/re-entry sama seperti `bidask:sol` yang sudah ada. Header format `pool.txt` dikelola bot; contohnya `pool.txt.example`. Hapus `#` saat worker entry jalan: baris ikut lagi di refresh berikutnya, tanpa restart.
- **PnL %**: satu fungsi `pnlFromEntry` (`src/meteora/positions.js`), dipakai exit, trailing, stop loss, bounce, DCA, riwayat, laporan, dan PnL saat tutup. Mode SOL: bila `initialCapitalSol` diketahui (> 0), `pnlSol / initialCapitalSol × 100`. Angka itu dicatat saat entry worker membuka posisi (SOL setoran) dan saat posisi manual diadopsi (deposit pertama datapi bila ada, kalau tidak `allTimeDeposits` saat adopsi). Rebalance in-place tidak menimpa. Rantai re-entry OOR kanan mewariskannya seperti `exitWarmupStartedAt`. Bila modal awal tidak diketahui: `pnlSol / (allTimeDeposits.total.sol − allTimeWithdrawals.total.sol) × 100`, lalu `pnlSolPctChange` bila modal bersih bukan angka, ≤ 1e-6, atau ≤ 1% dari setoran. Mode USD: `pnlUsd / modal bersih usd × 100`, lalu `pnlPctChange`. Setoran seumur hidup membengkak tiap rebalance in-place (tarik + setor ulang), jadi persen Meteora terlalu kecil dan modal bersih bisa negatif.
- **Exit**: per mode `bidask:<komposit>` (`bidask:double`, `bidask:token`, `bidask:sol`) atau `spot` (satu mode, span ≥ `SPOT_MIN_BINS`, OOR kanan ber-timer) — stop loss, OOR, trailing TP, dll. OOR kiri `spot` → tutup tanpa swap lalu buka posisi `bidask:token` satu-sisi (jual saat naik) di pool yang sama; token dilindungi dari sweep selama proses (`spot-fallback.js`, `open-token-position.js`). Yield rendah `spot` (24h Fee/TVL posisi `feePerTvl24h` segar, strictly < `SPOT_YIELD_CLOSE_BELOW_PCT` default 7, bertahan `SPOT_YIELD_CLOSE_BELOW_SEC` default 600 detik, tanpa syarat PnL) → close biasa + klaim + swap; bukan re-entry OOR. Tepat 7 atau di atasnya mereset timer. Data basi mereset. Stop loss/OOR/trailing tetap bisa menutup sendiri. `bidask:sol` (SOL-only, dari pool.txt atau diadopsi `classifyMode`) punya stop loss −40%, trailing trigger 10, warmup 30 menit yang menahan trailing dan arm indikator; indikator RSI/MACD/BB (`BIDASK_SOL_ENABLE_INDICATORS`, default mati) bila dinyalakan setelah warmup meng-arm trailing seperti `bidask:double`/`bidask:token` (bukan close langsung seperti spot); OOR kiri, yield, dan bounce mati. OOR kanan ber-timer seperti spot lalu membuka posisi `bidask:sol` baru (SOL-only, lebar bin sama, bentuk BidAsk, span tetap di bawah `SPOT_MIN_BINS`) memakai SOL hasil tutup. Rantai re-entry OOR kanan (spot dan `bidask:sol`) berhenti di `SPOT_REENTRY_MAX` atau `SPOT_REENTRY_MAX_HOURS` (default 3 jam sejak entry pertama rantai, 0 = tanpa batas), mana yang lebih dulu; saat batas waktu, tutup dan swap seluruh token mint itu ke SOL. Gerbang RSI re-entry (`SPOT_REENTRY_MAX_RSI`) dilewati selama rantai masih di dalam warmup exit mode itu (`SPOT_EXIT_WARMUP_MINUTES` untuk spot, `BIDASK_SOL_EXIT_WARMUP_MINUTES` untuk bidask:sol, dihitung dari awal rantai); setelah warmup, RSI di atas ambang menutup tanpa re-entry. Warmup 0 = gerbang RSI selalu jalan. Batas jumlah, batas waktu, cooldown, dan sewa non-refundable tetap berlaku selama warmup. Entry `pool.txt` untuk mode ini hanya baris CA + harga; rantai re-entry OOR kanan tidak menambah baris baru.
- **DCA**: averaging-down untuk mode di `DCA_ELIGIBLE_MODES` (default `bidask:double`); `spot` & `bidask:token` dikecualikan. Kuota sesi `state.dcaUsage` / `DCA_MAX_ADDS`. `DCA_TRIGGER_MODE=price` (default) meng-arm dari turunnya harga pool vs `entryPoolPrice` posisi utama (`DCA_ARM_PRICE_PCT` -20 / `DCA_ARM_PRICE_PCT_2` -35, satu acuan); trough, pantulan, dan delay konfirmasi ikut harga. `DCA_TRIGGER_MODE=pnl` memakai PnL seperti sebelumnya (`DCA_ARM_PCT` / `DCA_ARM_PCT_2`). Posisi utama tanpa `entryPoolPrice` jatuh ke mode PnL. DCA tidak memakai kuota 1-posisi-per-strategi.
- **Rebalance bidask:double**: `BIDASK_DOUBLE_REBALANCE_ENABLED` (default nyala). Tiap kelipatan `BIDASK_DOUBLE_REBALANCE_STEP_PCT` turun dari harga entry posisi itu sendiri, token di atas bin aktif dibentuk ulang jadi BidAsk. Saat harga pulih minimal satu step (`BIDASK_DOUBLE_SOL_REBALANCE_ENABLED`, default nyala), SOL di bawah bin aktif dibentuk ulang jadi BidAsk. Posisi utama dan posisi DCA masing-masing punya penghitung step. Tidak jalan bersamaan dengan DCA di pool yang sama, dan tidak jalan selagi konfirmasi pantulan DCA masih pending. `REBALANCE_MODE=inplace` (default) memakai instruksi di tempat supaya saldo wallet tidak ikut terseret; `withdraw` hanya menyetor jumlah yang keluar dari posisi. Range tidak disusutkan.
- **Rebalance bidask:sol**: `BIDASK_SOL_REBALANCE_ENABLED` (default nyala). Posisi SOL-only yang diadopsi exit worker. Tiap kelipatan `BIDASK_SOL_REBALANCE_STEP_PCT` (default 10) dari porsi bin yang sudah jadi token (bin di atas active, sama seperti spot), hanya bin token itu dibentuk ulang jadi BidAsk. Jalur otomatis tidak pernah menyentuh bin SOL (active dan di bawahnya), juga saat harga pulih. Sisi SOL hanya lewat tombol Telegram: bentuk ulang bin SOL yang ada jadi kurva BidAsk, range sama, tanpa bin baru, tanpa swap, bin token tidak ikut (`handleBidaskSolSolSideRebalance`). Ikut `REBALANCE_MODE` dan batas fee. Range tidak berubah. Penghitung step sisi token tidak ditulis oleh rebalance sisi SOL.
- **Entry bot Telegram** (`meteorabot-entrybot`, `src/worker-entrybot.js`): bot kedua dengan token `ENTRYBOT_TELEGRAM_TOKEN` (bukan `TELEGRAM_BOT_TOKEN`, karena satu bot hanya satu `getUpdates`). Chat = `TELEGRAM_CHAT_ID`, atau `ENTRYBOT_TELEGRAM_CHAT_ID` bila diisi. Token kosong = log lalu idle, tidak crash-loop. Bot ini tidak membuka posisi: dia menambah baris `pool.txt` (size kosong supaya `ENTRY_DEFAULT_SIZE_SOL`) lewat wizard `/entry` (Bidask SOL setelah CA: tombol Entry sekarang menulis `now`, Harga target tetap minta angka), lalu memantau sampai `meteorabot-entry` yang mengeksekusi. `/antrean` dan `/batal` seperti dijelaskan di README. State di `state/entrybot.json`.
- **Telegram tombol** (`TELEGRAM_BUTTONS_ENABLED`, default nyala): hanya pesan rutin Position Status (`buildStatusMessage` / `notifyStatus`) yang membawa tombol inline `♻️ <simbol>` dan `⚡ <simbol>`. Simbol = nama pair tanpa akhiran `-SOL`; kalau akhiran itu tidak ada, nama penuh dipakai. `bidask:token` hanya `⚡ <simbol>`. Simbol lebih dari 10 karakter: satu tombol per baris. Klik ♻️ mengganti baris itu jadi `Token`, `SOL`, dan `Batal` (selalu satu baris, tanpa emoji dan tanpa simbol). Memilih sisi langsung mengantre — tidak ada langkah Ya lagi — lalu toast dan keyboard kembali. Zap Out tetap `✅ Ya, zap out <simbol>`. Callback lama tanpa sisi (kode `r` / `R`) hanya membuka pilihan sisi. Alert entry/exit/rebalance lain tetap tanpa tombol. Worker PM2 terpisah `meteorabot-telegram` (`src/worker-telegram.js`, log `logs/telegram-out.log` & `logs/telegram-error.log`) long-poll `callback_query` saja, hanya dari `TELEGRAM_CHAT_ID`. Klik mengubah keyboard pesan itu lalu toast; tidak ada pesan baru. Konfirmasi menulis `{id, action: zap_out|rebalance, side: token|sol, position, requestedAt}` ke `state/telegram-commands.json` (kunci file, bukan `state.json`). Worker ini tidak menutup posisi dan tidak rebalance. `meteorabot-exit` mengambil antrean tiap siklus. Zap Out = close yang sudah ada, alasan `manual_telegram` (label "manual (Telegram)"), swap sisa token ke SOL, rantai re-entry OOR kanan tidak dilanjutkan. Rebalance jalan segera, pemicu step diabaikan, `REBALANCE_MODE` dan batas fee tetap. `spot` dan `bidask:double`: sisi token = rebalance sisi token mode itu, sisi SOL = rebalance sisi SOL mode itu, lalu step terakhir sisi itu dicatat. `bidask:sol`: kedua sisi tampil; sisi token = rebalance token yang sudah ada; sisi SOL = rebalance manual baru (jalur otomatis tidak pernah memanggilnya). `bidask:token` tidak punya tombol rebalance. Bila sisi itu kosong, pesan `Tidak ada yang bisa di-rebalance di sisi itu` dan perintah ditandai selesai. Perintah >10 menit atau posisi yang sudah hilang tidak dijalankan. `false` = teks status persis seperti biasa, tanpa keyboard.
